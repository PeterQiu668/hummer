# HUMMER 私有 Alpha 人工审批执行包（2026-10-07）

## 要批准的不是“上线”，而是一场可随时停止的受监督实验

目标是在 1 台 Relay/Desktop 主机与 1 台干净 Windows 节点之间，完成
`fs.read.attest.v1` 的真实跨机闭环：派一个明确文件摘要任务，人工批准，
执行一次，只返回字节数与 SHA-256，并独立验证回执。

本执行包不授权公开互联网暴露、生产数据、通用 Shell/网络/写入、付款、
删除、提权、自动批准、代码签名采购或真实支付。任何一项需要扩大范围时
立即停止并重新审批。

## 当前已具备

- 本机首启不再需要复制 tenant/account；Desktop main 认领后才启动 Relay/Node；
- Desktop 持久 outbox、人工审批、撤销/超时、一次性 task grant 与结果回执；
- 唯一生产执行器为只读摘要 `fs.read.attest.v1`，不返回文件正文；
- 最新封存证据 root 为
  `0d035b1fae390ec6b424ef181d2ce407f8249a92f227e47b3d65b9446ad98897`。

## 仍需人工提供或批准的外部条件

| 项目 | 需要丘总提供/批准 | 默认安全选择 | 不批准时 |
|---|---|---|---|
| 第二台 Windows | 一台可重置的非生产机器与现场操作者 | 新建本地测试账户，不接生产资料 | 不做真双机，只保留本机证据 |
| 私有网络 | 指定现有内网/VPN；是否允许改防火墙 | 仅允许两台指定主机和一个端口 | 不开放监听端口 |
| TLS | 指定现有私有证书/内网网关；是否允许新增反向代理 | TLS 在现有受信网关终止，Relay 继续只监听 loopback | 不传输 badge，不做远端测试 |
| 节点 badge | 批准生成一枚 8 小时、单租户、单节点、最小 scope 的测试 badge，并指定安全传递渠道 | 一次性人工配置，测试后撤销；不写 Git/聊天/报告 | Node 不加入 |
| 安装包 | 批准在目标机运行当前未签名内测包 | 现场监督、先核 SHA-256、记录 SmartScreen；不购买签名证书 | 改为开发者 CLI，不计入安装指标 |
| 测试数据 | 指定一个低敏、可公开哈希、≤1 MiB 的文件 | 专门生成 canary 文本，正文不进日志/回执 | 不用真实业务文件 |
| 真实专家 | 指定 1 位愿意参与 30–45 分钟的操作者 | 仅完成只读摘要任务，不录屏、不采集输入 | 只测技术，不声称市场验证 |

## 推荐拓扑（方案 A）

```
目标 Windows Node -- HTTPS --> 私有 TLS 网关 -- loopback HTTP --> HUMMER Relay
                                               |
                                  Desktop 人工批准与查看回执
```

- Relay 保持现有 `127.0.0.1` 约束，不直接暴露到局域网或公网；
- 网关只允许目标 Node 和 Desktop 主机，禁止匿名访问与目录浏览；
- Node 使用 HTTPS Relay URL，badge 只进入进程环境并在读取后删除；
- 先跑连通/过期/错租户负例，再跑唯一的正常任务。

方案 B 是在两机间使用已存在且已批准的私有覆盖网络；如果需要新安装
VPN、改路由或开账号，它仍属于单独 L3 动作。公开域名或公网端口不在本轮选项中。

## 逐项执行与证据

### 阶段 0：只读预检（不改外部状态）

1. 记录两台机器 OS、时区、Node/Codex 版本和目标安装包 SHA-256。
2. 确认目标文件位于专用 workspace，大小不超过 1 MiB，且不是链接、
   junction、reparse point 或硬链接。
3. 确认 Relay/Desktop 主机有足够磁盘，并备份当前非秘密配置。
4. 预期证据：`preflight.json`、安装包哈希、操作者与设备匿名编号。

预检必须从 `docs/release/private-alpha-preflight.template.json` 复制到本轮独立
工作目录后填写，禁止把真实 badge 值写入文件。填写完成后运行：

```powershell
npm run validate:private-alpha:preflight -- <本轮-preflight.json>
```

只有输出 `status: ready` 且退出码为 0 才能请求进入阶段 1。未填写模板必定
输出 `status: blocked` 和退出码 2；校验器只读本地 JSON，不联网、不启动服务、
不修改网络或防火墙。布尔批准字段只能证明材料完整，不能替代丘总的真实授权记录。

### 阶段 1：受控安装与接入

1. 操作者开始计时，安装/启动 Desktop 或 Node；开发者不得替操作者点击。
2. Desktop 创建身份，验证 local stack 从 `waiting_for_identity` 进入 `running`。
3. 经批准的私有 TLS 网关上线；先验证无 badge、错 badge、过期 badge 均拒绝。
4. 目标 Node 使用最小 badge 注册；验证第二个伪造 nodeId/tenant 被拒绝。
5. 预期证据：首启耗时、安装日志、TLS 证书指纹、拒绝用例、节点在线回执。

### 阶段 2：首个真实任务

1. Desktop 明确选择在线节点、相对路径和读取上限。
2. 确认前验证零入队/零执行；批准页逐字核对节点、路径、期限、单次使用。
3. 人工批准后执行一次；返回文件字节数和 SHA-256，不返回正文。
4. 用独立验证器检查 OutcomeReceipt，并确认同一 grant 重放被拒。
5. 预期证据：TaskEnvelope 摘要、批准事实、节点回执、独立验证 exit 0、
   重放/错租户/撤销负例。

### 阶段 3：5 次 shadow 与访谈

1. 同一任务以 5 个不同 run 重做，成功线为至少 4/5，且每次证据独立。
2. 记录首任务总耗时、失败点、是否需要开发者技术救援。
3. 只询问再次使用意愿、可接受价格与愿付费解决的风险；不接支付。

## 立即停止条件

- 需要公网暴露、放宽 Relay loopback、关闭 TLS 验证或把 badge 写入文件/聊天；
- 需要开放 Shell、网络、写入、删除、付款或提权执行器；
- 目标机出现生产数据、未知账户、未知证书或无法解释的后台进程；
- 30 分钟内非开发者不能完成首个任务；
- 任何负例被静默放行，或回执无法独立验证；
- 需要删除证据、改写 Git 历史或覆盖失败轮才能继续。

## 回滚顺序（不做数据删除）

1. 在 HUMMER 中撤销测试 badge/授权并停止接单；
2. 通过受控 stop 关闭 Node、Relay、Desktop，确认 SQLite/WAL 句柄释放；
3. 关闭私有 TLS 网关监听并恢复原防火墙规则；
4. 保留脱敏日志、失败证据和配置哈希，不批量删除状态目录；
5. 目标机若需卸载或删除数据，单独列明精确路径并再次请求人工确认；
6. 运行本机全量回归与证据校验，形成 before/after diff 和运行回执。

## Go / No-go

只有以下条件同时成立才进入 3–5 位种子用户测试：

1. 非开发者在 30 分钟内完成安装和首任务，目标 15 分钟；
2. 5 次 shadow 至少 4 次成功，无开发者改库或复制 task token；
3. TLS、错租户、过期、撤销、重放负例全部失败关闭；
4. 至少 2 位用户愿意再次使用“派活 + 审批 + 可验证回执”；
5. 至少 1 位用户愿意讨论付费试点，并能说出具体风险或成本。

任一核心指标失败就停止扩平台，转为内部可信交付台或开源证据组件。

## 需要的明确批准文本

在真正执行前，至少需要确认：

> 批准 HUMMER 方案 A 的受监督私有 Alpha：允许在指定的两台 Windows 上
> 运行现有内测包；允许为指定私有端口配置 TLS 网关与最小防火墙规则；
> 允许生成并安全传递一枚 8 小时单节点测试 badge；只使用指定低敏 canary
> 文件和 `fs.read.attest.v1`；不公开部署、不购买证书、不接支付、不删除数据。

批准时还需补充：两台设备、私有网络/TLS 入口、操作者、canary 文件和
安全传递渠道。未收到这些具体值前，本执行包保持“待审批”，不得执行。
