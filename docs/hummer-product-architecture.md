## 1. 执行摘要

**一句话定位：Hummer 不做"又一个 Agent 搭建平台"，而做「数字员工的人事与信任基础设施」——企业雇佣、管理、考核、追责数字员工的编制管理层（Digital Workforce HRM + Trust Layer）。**

三个支撑判断：

1. **搭建平台已是红海，管理平台是空白。** 海外 13 家、国内 12 家调研显示：Agent 构建工具（低代码画布、RAG、工作流）已被云厂商和 IM 巨头做穿；但「数字员工的雇佣—授权—考核—追责—结算」这条 HRM 链路，海外刚出现雏形（OpenAI Frontier 的入职/绩效循环、Microsoft Agent 365 给 agent 组织架构位置、ServiceNow 按角色卖 AI Specialist），国内完全无人做全。Forrester 2026 预测「头部五大 HCM 平台将提供数字员工管理能力」——这正是 Hummer 原型三年前就画出的东西。
2. **原型的核心叙事恰好踩中行业公认空白。** 责任链问责、审批熔断、证据链、试岗认证、专家共创——分别对应调研发现的五大空白：跨平台责任链缺失、写操作治理缺失、可靠性透明度缺失、成本可预测性缺失、专家知识交易市场缺失。原型的方向是对的，缺的是把「顺利路径的演示」补成「含验收、失败、追责、结算、分成的完整闭环」。
3. **Gartner 预测 40% agentic 项目将因「成本失控、价值不清、风控不足」被取消——把这三大死因逆向做成产品能力（Agent FinOps、ROI 报表、治理内建），就是幸存者卖点。**

## 2. 市场调研核心结论

### 2.1 海外格局（13 家：Agentforce / ServiceNow / Microsoft / Google / OpenAI / Sierra / Decagon / Lindy / Relevance / Artisan / 11x / Dust / Glean / Devin）

**七条行业共识能力**（做数字员工平台的入场券）：

| # | 共识能力 | 代表实现 |
|---|---|---|
| 1 | MCP 事实标准（头部双向 + 企业管控） | 11/13 家支持；Glean 注册制、Devin 白名单 |
| 2 | Agent 独立身份 + 最小权限 | Entra Agent ID、Salesforce agent user 默认零权限 |
| 3 | HITL 前移到计划期 / 动作分级授权 | Devin Interactive Planning、Dust 工具 stake 分级、Artisan Copilot→Autopilot 渐进信任 |
| 4 | supervisor/manager 多 agent 分层编排 | MultiDevin（1 经理+10 工人）、ServiceNow Orchestrator |
| 5 | 上线前模拟评测 + 运行时可观测 | Salesforce Testing Center、Decagon test-driven（类 CI 回归） |
| 6 | 席位+消耗混合定价；outcome-based 成 CX 垂直武器 | Sierra 按解决收费、Decagon $0.50/解决 |
| 7 | Agent 拟人化管理（入职/考核/组织位置），竞争焦点转向「agent 控制平面」 | OpenAI Frontier、Microsoft Agent 365 |

**五条行业空白**（差异化机会）：

1. **成本可预测性**——全行业头号客户抱怨（Agentforce 真实 TCO 数倍于标价、Devin 失败 session 也烧钱、credits 黑箱普遍）。「事前报价、失败不收费、预算硬顶」无人做到。
2. **Bad case → 改进的自动化闭环**——监控看板已普及，失败到修正仍靠人肉改 prompt。
3. **跨厂商 agent 治理与责任链**——控制平面互相割裂，A2A 只解决通信不解决问责；「出错追溯到人类 owner 与审批记录」是空白。
4. **可靠性透明度**——没人敢公布真实成功率（Devin 被第三方实测 ~15%）；「任务级置信度预估 + 成功率 SLA + 按可靠性分级接单」是空白。
5. **中型市场断层**——巨头绑生态且 100/150 席起售；Sierra/Decagon 靠驻场服务超大客户（年费 $150K+）；SMB 自助工具治理不达标。「自助上线 + 企业级治理」的 mid-market 方案是结构性空白。

### 2.2 国内格局（钉钉 / 飞书 aily / 企微 / 百炼 / 百度千帆 / 腾讯元器·ADP / 扣子·HiAgent / 实在智能 / 来也 / 壹沓 / 销售易·微盟·用友金蝶；警示案例：澜码）

**六条国内特有洞察**：

1. **IM 是数字员工的"户口所在地"**——第一入口是钉钉/飞书/企微（入通讯录、进群被 @、走审批流）；钉钉"AI 小钉"、飞书"智能伙伴常驻联系人列表"是海外没有的形态。
2. **双备案制合规是硬门槛与护城河**（算法备案 + 大模型备案，2025 起企业内部模型也纳入备案）。
3. **私有化/信创需求远超海外**，软硬一体机是中国特色交付。
4. **"专家知识服务化"是差异化主线**——百度用 10 万小时行业实操数据预训练岗位、壹沓打包"虚拟专家团队"。国内客户买的不是工具而是"带经验入职的员工"，本质是 BPO 替代而非 Copilot 增强。
5. **定价走向对标人力成本 / RaaS**（钉钉 AI 差旅专员对标人力薪资、金蝶按行程数收费）。
6. **创业公司窗口收窄**——纯水平搭建平台已是云厂商+IM 巨头战场（澜码 2025 年倒闭为戒）；存活独立厂商靠 RPA 存量或深垂类 Know-How。

**五个国内市场空白**：① 跨 IM/跨平台的数字员工"人事系统"（统一雇佣/考核/审计/成本核算的中立层）；② 备案合规即服务；③ 按结果计费的计量与审计基础设施（RaaS 卡在"结果谁来验证"）；④ 深业务系统**写操作**的治理层（现有平台强读弱写，"操作审批流+回滚+责任认定"是金融/国企放开写权限的前提）；⑤ 专家知识资产交易市场（专家封装经验为技能包、按调用分成的 C2B，无人做成）。

### 2.3 基础设施与标准（2026 参考能力栈）

| 层 | 2026 年标准答案 |
|---|---|
| 协议 | MCP（工具接入，AAIF/Linux Foundation 治理）+ A2A v1.2（跨 agent，签名 Agent Card）+ 自建 MCP Gateway（鉴权/白名单/审计/限流——安全事故频发，网关是企业部署前置条件） |
| 身份与凭证 | Agent = IdP 中的一等身份（NHI），有 owner、有生命周期（入职/转岗/离职即吊销）；Token Vault 凭证托管，agent 只拿短期任务作用域 token |
| 运行时与编排 | Claude Agent SDK 执行体（hooks/subagents/原生 MCP，与"受控数字员工"心智最匹配）+ 自研/LangGraph 式 durable 编排；编排定义必须代码化可导出（OpenAI Agent Builder 上线一年即关停为戒） |
| 安全 | 注入不可根除是设计前提：指令层级 + 确定性护栏 + 沙箱执行 + 高危动作强制 HITL（公认单点最有效）+ 可回滚 |
| 可观测与治理 | OTel GenAI semantic conventions 发 trace；每个 agent 行为可回放到 trace + 审批记录；治理映射 NIST AI RMF / ISO 42001 / EU AI Act（2026-08 高风险生效）+ 国内双备案 |
| 评测与上岗认证 | 岗位沙箱任务集（τ²-bench 式：模拟用户+工具+政策遵守）→ trajectory 轨迹级评分 → 认证绑定权限分级（只读→审批执行→有限自主）→ 版本变更重新认证。**评测资产（数据集/rubric/判分器）是平台核心 IP** |

## 3. 原型闭环审计：七大闭环与 Top 10 缺口

沿七个产品闭环审计原型（工作/信任/成长/商业/数据/组织/生态），总体判断：**原型把"顺利路径的前半程"（意图→执行→留痕）演示得很丰满，但所有闭环的「回程环节」（验收、追责、结算、回流、分成）和「异常路径」（失败、超时、出错、分歧、淘汰）系统性缺失。**

| 闭环 | 已有 | 关键断点 |
|---|---|---|
| A 工作 | 意图→任务→执行→交付 4 环完整 | 验收有"标准"无"动作"；状态机无 failed/rejected/overdue；交付物无业务出口（不发客户/不回写 CRM）；无结算 |
| B 信任 | 留痕最强（审计/证据/责任链叙事） | 授权是布尔开关（无额度/有效期/签署）；"专家保障"纯文案无兑现机制（无呼叫入口/SLA/工单）；无赔付政策 |
| C 成长 | 四套成长模型都建模了 | 试岗无内容无终点（"1/7 天"硬编码）；考核指标与企业 KPI 无对齐；淘汰/晋升无触发器；SOP 回写后不分发 |
| D 商业 | 4 套餐定价橱窗 | 套餐与 token 计量互不相认；无账单中心；**无 ROI 报表（续费无依据）**；专家分成零建模 |
| E 数据 | 知识中枢 4 步骤骨架 | 步骤间无数据流动；**冷启动空白**（"3 分钟部署"与"知识从零建设"矛盾）；产出不回流为知识资产 |
| F 组织 | 五级责任链、6 大企业群 | **真人只有老板一人**（高管无工作台、一线员工不存在）；组织架构硬编码；分歧无仲裁；会议行动项不转任务 |
| G 生态 | 6 位专家展示位 | **供给侧整条链 0 覆盖**（入驻/共创工作台/上架/分成/声誉全无）；6 专家挂 11 环节撑不起 54 岗位承诺 |

**Top 10 缺口（按影响排序）**：① 验收环缺失（地基）② 交付物无业务出口 ③ 专家保障无兑现机制 ④ ROI 与账单双缺失 ⑤ 一线员工/多角色入口缺失 ⑥ 试岗-转正-淘汰断头 ⑦ 老板收件箱未实现（各闭环异常路径的统一承接面）⑧ 供给侧生态全缺失 ⑨ 数据冷启动空白 ⑩ KPI 对齐与授权仪式缺失。

其中 ①②③⑦ 共享同一产品机制底座：**以老板收件箱为异常汇聚面、以 RiskAlert 审批网关为动作出口**——投入最小、优先补齐。

## 4. Hummer 独有解决方案：五大差异化支柱

将「市场空白 × 原型已有资产 × 闭环缺口」三者取交集，得到五个别人没做、我们已有雏形、客户真实买单的支柱：

### 支柱一：责任链问责系统（Accountability Chain）
> 对应：海外空白 3（跨厂商责任链）+ 国内空白 4（写操作治理）+ 原型资产：五级责任链、RiskAlert、审计链

- 每个数字员工是 IdP 中的一等身份，**必有一个人类 owner**，沿「老板→老板分身→高管分身→真人高管→数字员工」的责任链注册。
- 每个高危动作可展开**责任链快照**：谁授权、依据哪版 SOP、哪条策略放行、专家是否认证——回答企业采购的第一问「出事谁负责」。
- 写操作治理三件套：动作分级授权（只读→审批执行→有限自主，渐进信任）+ 审批熔断（策略引擎在工具调用前拦截）+ 可回滚（交付出口动作全部可撤回/留痕）。
- 审计账本 hash chain + 证据内容寻址（SHA-256），支持第三方审计导出——这也是「按结果计费谁来验证」（国内空白 3）的技术答案。

### 支柱二：上岗认证与绩效体系（Certification & Performance）
> 对应：海外空白 4（可靠性透明度）+ 行业共识 5/7 + 原型资产：试岗五阶段、淘汰、SOP 版本、质量飞轮

- **数字员工持证上岗**：每个岗位自带沙箱试岗任务包（模拟用户+真实工具+政策遵守 rubric），trajectory 级评分，达标发证并绑定权限等级；模型/SOP/工具变更必须重新认证。
- **可靠性透明化为卖点**：市场上每个数字员工公示认证分、政策遵守率、历史转正率——用可验证性打击行业性的 "agent washing"。
- 试岗 7 天有内容有终点：试岗报告卡 → 强制三选一（转正并授权 / 延长试岗 / 退回）。转正后进入月度考核（指标来自企业 KPI 对齐器，定制向导选的业务目标直接落为考核基线）。
- 质量飞轮产品化：bad case 自动归因 → 自动生成回归用例 → 生成 SOP 修正候选 → 沙箱回归 → **人审后灰度发布到所有同岗位 Agent**（含影响面清单与回滚）——补上海外空白 2。

### 支柱三：专家共创生态（Expert Marketplace，供给侧）
> 对应：国内空白 5（专家知识交易市场）+ 国内主线 4（专家知识服务化）+ 原型资产：专家保障/市场/套餐

- 供给侧四环补全：专家门户（入驻/资质审核/签约）→ 共创工作台（SOP 模板化编辑 + 沙箱试跑 + 提交认证 + 签名上架）→ 分成结算（按其 Agent 的 hires × 订阅额，收入看板）→ 专家声誉（其 Agent 的转正率/淘汰率反算专家评级，评级决定曝光与分成比例——把成长闭环数据变成生态闭环货币）。
- **专家保障从文案变成 SLA 产品**：事故触发专家介入工单，专家以 `expert` 角色进入对应频道处置，处置记录入审计；响应 SLA 分级与套餐挂钩。
- 这是平台的网络效应护城河：云厂商能复制搭建工具，复制不了"1000 个行业专家的认证 SOP 资产 + 声誉体系"。

### 支柱四：经营级 ROI 与 Agent FinOps
> 对应：海外空白 1（成本可预测性，全行业头号抱怨）+ Gartner 40% 取消率三大死因 + 原型资产：tokensToday/costToday 字段

- **成本确定性承诺**：任务事前预算报价、预算硬顶（超限熔断转人工）、**失败任务不计费**——直接反击 "Devin 失败也烧 ACU" 式的行业痛点。
- 账单中心：部门/员工/任务三级成本归因，预算告警进老板收件箱。
- **月度经营 ROI 报告**（续费武器）：完成任务数、验收通过交付物数、等效人时、对比同岗位人力成本、专家介入次数——自动生成，主动推送，让老板拿着报表向 CFO 续费。
- 定价对标人力成本（国内趋势）：套餐 = 编制费（含认证/治理/专家 SLA），用量 = 绩效工资（透明计量），为 RaaS（按结果计费）预留计量与验证基础设施。

### 支柱五：闭环工作系统（Work OS with Exits）
> 对应：闭环缺口 ①②⑤⑦ + 国内洞察 1（IM 户口）+ 原型资产：9 类消息、任务详情、会议流、3D 指挥中心

- **验收工作台**：acceptance 逐条判定、验收人规则、不通过三选一（打回/转人工/降级）；任务状态机补全 failed/rejected/cancelled/overdue 与回退路径。
- **交付出口**：每类交付物定义"生效动作"（发送客户/回写 CRM/发布），出口动作走审批网关——让 AI 干的活真正进入经营流。
- **老板收件箱**：审批/阻断/卡住/待验收/异常五类事件的统一承接面 + 移动端推送——所有闭环异常路径的落点。
- **多角色工作台**：老板总控 / 高管审批与验收 / 一线员工"我的 AI 同事"轻量入口（派活、催办、验收）——买单者与使用者不再割裂。
- **IM 中立层**：不与钉钉/飞书/企微竞争入口，数字员工可作为 bot 进驻三大 IM 被 @ 和派活，Hummer 是背后的编制/治理/结算层（国内空白 1「跨 IM 数字员工人事系统」）。

**目标市场**：50–1000 人的中型企业（海外空白 5 的结构性断层）+ 需要写操作治理的行业（先泛商贸/服务，后金融国企）。**交付形态**：SaaS 自助上线为主（拒绝驻场重交付——澜码之戒），预留私有化/信创版本。

## 6. 落地路线图（产品视角，与技术底座 MVP 对齐）

### Phase 0 — 原型补全（演示即闭环，2–3 周）
目标：让现有 mock 原型把"闭环"故事真正演完，支撑融资/客户演示。
补：验收工作台（含失败/打回）、交付出口动作、老板收件箱（五类事件）、试岗报告卡与转正三选一、授权仪式页、专家介入工单流、ROI 报告页、专家共创工作台（mock 版）。
> 全部沿用现有 mock 数据即可，重点是把 Top 10 缺口在 UI 层闭上。

### Phase 1 — 可信 MVP（一条真实闭环，6–8 周）
与技术底座 MVP 重合：1 个真实数字员工（Claude Agent SDK）+ 1 个真实 MCP 工具，跑通「任务下发→执行→tool_call 事件→产出物→证据入链（真 SHA-256 + hash chain）→策略熔断→人工审批→验收→交付出口→审计可回放」。前端接对话流/审批/证据库/收件箱四个真实页面。
**验收标准：给一家种子客户真实用 2 周，产出第一份真实 ROI 报告。**

### Phase 2 — 编制管理 V1（3–4 个月）
责任链委派 + A2A 双向状态机、上岗认证流水线（沙箱任务集 + trajectory 评分 + 权限分级）、多角色工作台、KPI 对齐与月度考核、账单中心 + 预算硬顶 + 失败不计费、IM bot 分发（先钉钉或企微其一）、多租户 + RBAC/ABAC、数据接入向导与冷启动 playbook。

### Phase 3 — 生态与飞轮 V2（持续）
专家门户/共创工作台/分成结算/声誉体系上线（供给侧冷启动：先签 10–20 位垂类专家共建认证 SOP 库）、质量飞轮自动化（归因→回归→灰度）、知识资产月报、私有化/信创版本、RaaS 计费试点、合规即服务（双备案辅助）。

### 关键风险（产品层，3 条）
1. **供给侧冷启动**：专家生态是护城河也是最慢的一环 → Phase 2 前先以自营专家（创始团队+顾问）冒充首批供给，跑通认证与分成机制再开放。
2. **中立层被 IM 巨头挤压**：钉钉/飞书随时可能自己做"编制管理" → 靠两点防御：跨 IM 中立性（大企业多 IM 并存是常态）+ 认证/审计资产的可迁移性承诺。
3. **"信任"卖点被一次事故击穿**：早期任何一次数字员工重大出错都会反噬叙事 → 前 100 家客户强制保守默认（全部动作 require_approval 起步，渐进放权），宁可牺牲自动化率。

## 7. 硬性成本评估（做完一整套系统闭环）

> 口径：国内 2026 年成本水平，人民币；人力按全成本计（含五险一金社保，约工资 × 1.35）。硬性成本四大块——**人力、模型/云、合规、生态冷启动**，人力占 70% 以上。

### 7.1 分阶段投入

**Phase 0 — 原型补全（2–3 周）**：纯前端 mock 层改造，1–2 名前端 + AI 辅助开发。**≈ 3–8 万**。

**Phase 1 — 可信 MVP（6–8 周）**：

| 项 | 配置 | 成本 |
|---|---|---|
| 人力 | 后端×2、前端×1、全栈/DevOps×1、产品设计×0.5（全成本 4–7 万/人月） | 45–80 万 |
| LLM API | 开发调试 + 认证流水线沙箱评测（评测是吃 token 大户）+ 种子客户试用 | 2–5 万 |
| 云基础设施 | PG/Redis/OSS/K8s 最小集 | 0.5–1 万/月 |
| **小计** | | **约 55–95 万** |

**Phase 2 — 编制管理 V1（3–4 个月）**：

| 项 | 配置 | 成本 |
|---|---|---|
| 人力 | 7–9 人（后端×3、前端×2、算法/评测×1、产品×1、设计×0.5、测试×0.5） | 180–320 万 |
| 合规 | 备案 + 等保 + 法务（见 7.2） | 30–70 万 |
| LLM + 云 | 多租户 + 评测 CI 常跑 | 8–15 万 |
| IM 生态入驻 | 钉钉/企微 ISV 认证、开放平台费用 | 1–3 万 |
| **小计** | | **约 220–410 万** |

**Phase 3 — 生态与飞轮（持续期，仅列启动性硬成本）**：
- 专家生态冷启动：签约 10–20 位垂类专家共建认证 SOP 库，每位签约金/预付分成 2–5 万 → **30–100 万**（护城河的价格，省不掉）
- 私有化/信创版本适配（如做）：单独 **50–150 万** 级工程投入
- 团队扩到 10–12 人后月 burn：**70–110 万/月**

### 7.2 合规成本单列（国内硬门槛）

| 项 | 说明 | 成本 |
|---|---|---|
| 算法备案 / 生成式 AI 应用登记 | 调用已备案基础模型走应用登记路径，远轻于自训模型备案——**决定模型策略：MVP 阶段不碰自研/深度微调** | 10–25 万 |
| 等保三级 | 金融/国企客户采购前提；测评 + 整改 | 15–30 万，年复测 5–10 万 |
| 数据合同/隐私法务 | 数字员工触达客户 CRM/资金数据，DPA 条款必须专业 | 5–15 万 |

模型双轨注意：若以 Claude 为执行内核（技术最优），国内商用交付存在备案通路问题——现实方案是 `AgentRuntime` 抽象层挂国产已备案模型对外交付、Claude 用于内部研发与海外版；双轨约增加 10–15% 工程成本（已含在上述区间）。

### 7.3 汇总：两种打法

| | 标准团队打法 | 精简 AI 驱动打法 |
|---|---|---|
| 团队 | 7–9 人 | 3–4 名资深全栈 + 重度 AI 辅助开发 |
| 从零到 V1 可售卖（约 7–9 个月） | **380–580 万** | **180–280 万** |
| 上线后月 burn | 70–110 万/月 | 35–55 万/月 |

精简打法的代价：交付节奏对个人依赖极高；合规与评测资产建设是日历时间，无法用人力压缩。

### 7.4 比总投入更致命的：单位经济模型

按套餐定价反推：初创版 ¥8,800/月 ÷ 7 个数字员工 = **每员工月收入 ¥1,257**。而一个真实干活的数字员工（每天 10 任务 × 每任务约 20 万 token 工具循环）用旗舰模型的 token 成本约 **¥1,500–2,500/月——毛利为负**。这正是调研中"Agentforce 真实 TCO 数倍标价、credits 黑箱"等行业丑闻的根源。

三条必须提级为生存问题（而非功能）的对策：
1. **模型分层路由**：例行任务走轻量模型（成本降 5–10 倍），复杂决策才走旗舰——单员工成本可压至 ¥300–800/月，毛利转正。**这是 P0 不是优化项。**
2. **预算硬顶 + 失败不计费**：不只是差异化卖点，是自我保护——一个循环失控的 agent 一晚能烧掉一个客户全年毛利。
3. **套餐含量 + 超量计费**第一天就定义清楚（商业闭环审计已指出：原型的包月套餐与 token 计量两套账互不相认）。

**结论**：做到可售卖的完整闭环（V1）硬性投入 **200–580 万**（取决于打法），周期 7–9 个月；合规（30–70 万）与专家冷启动（30–100 万）是无法用技术压缩的日历成本；真正决定生死的不是一次性投入，而是单员工 token 成本 vs 定价的毛利结构。

## 8. 开放问题：盲区清单与创始人假设压力测试

> 本章记录前置分析的边界：哪些问题尚未回答（8.1）、创始人对部分问题的初步假设及其压力测试结论（8.2）、以及验证优先级（8.3）。原则：**桌面分析到此为止，以下问题只能靠一手证据回答。**

### 8.1 七个盲区（前置分析未覆盖的部分，按严重程度排序）

1. **零客户证据**：整条分析链是"原型→竞品→空白→方案"的由内向外推导，无客户访谈、无付费意愿验证、无 demo 反馈。"空白"可能意味着机会，也可能意味着没需求。
2. **调研与方案的自相矛盾未解决**：调研结论说"纯水平平台创业窗口关闭，存活者退守垂类"，方案却是水平信任层。缺 beachhead 行业选择分析——很可能应先在一个垂直行业跑通七个闭环再水平化。
3. **只算了"建"的钱，没算"活到打平"的钱**：月 burn 70–110 万 ÷ 客单 1–3 万/月 → 需 30–100 家付费客户打平，企业级销售需 12–24 个月 → 真实资金需求 1,500–2,500 万级（含销售团队与 CAC），远超建设成本 580 万。
4. **平台依赖可行性未尽调**：钉钉/企微/飞书开放平台对第三方 bot 的通讯录/组织架构/审批流权限边界，及对"管理型 agent"的 ISV 政策。
5. **法律责任结构未调研**：数字员工致损的法律定性、"专家兜底"的法律结构（责任是否弹回平台）、AI 责任险在国内的可保性——决定支柱一/三的承诺能否写进合同。
6. **单位经济模型无实证**：7.4 的 token 成本全部为推算，未跑过真实任务。
7. **竞争响应未推演**：编制管理层被验证后，钉钉抄"数字员工花名册"的周期？HiAgent"持证上岗"+市场分成的演进速度？

### 8.2 创始人假设压力测试（2026-07 记录）

**假设 1：「token 成本后期全部换成本地部署模型，几乎一次性投入，并发高再扩充」**
- 成立的部分：本地化/国产芯片是信创与备案的合规通路，是 Phase 3 的正确规模化选项。
- 不成立的部分：①"一次性"是错觉——折旧、电力、推理平台工程师（60–100 万/年）之外，最大隐性成本是**开源模型半年一代 × "模型变更必须重新认证"（本方案自己的规则）= 每次换模型全量回归**；②利用率经济学：早期负载小且波动大，闲置 GPU 纯亏，行业路径是 API→专属推理→自建，拐点为"稳定月推理支出 > 硬件月摊销 2–3 倍"，是账单触发的决策而非提前锁定；③可靠性风险：开源模型的长链工具调用可靠性差距会直接拉低"上岗认证分"——省 token 钱可能拆掉支柱二（可靠性透明化）的台。
- **修正立场**：V1 毛利必须在 API 价格下成立（模型分层路由仍是 P0）；本地部署作为规模化+信创选项挂在 Phase 3，触发条件写进财务模型。

**假设 2：「飞书肯定开放（有额度限制）；后面做自己的 IM app 形成自己的生态」**
- 成立的部分：不被平台卡脖子的"自有交互面"诉求是对的；飞书开放性已部分确认。
- 不成立的部分：①企业 IM 是创业公司坟场（三巨头十年百亿投入，网络效应+替换成本最强品类）；②与支柱五"IM 中立层"定位正面冲突——自建 IM = 放弃中立性、变成第四个 IM；③一线员工"多装一个 IM"的采用阻力比"现有 IM 加 bot"高一个数量级，直接杀死组织闭环的任务供给。
- **修正立场**：自有 Web 工作台 + 移动 App 做"驾驶舱"（收件箱/审批/验收/ROI 等深度交互，本来就在架构中），IM 只做"触角"（通知/@/轻审批卡片）——触角被限流，驾驶舱仍在自己手里。**不做 IM**。待验证：钉钉/企微（目标客群大盘所在）的 bot 权限边界与飞书额度的具体量级。

**假设 3：「数字员工任何关于钱的决策都交给人审判后才能执行，责任回归人本身」**
- 成立的部分：与行业共识一致（高危动作 HITL 是公认单点最有效防御），且兼容渐进信任模型。
- 风险：①"关于钱"边界模糊（含报价的邮件？价格建议？）——定义过宽 → 审批洪水 → 审批疲劳 → 盲批 → "责任剧场"（人形式上批了实质没判断，责任照样不清）；②责任回归人的前提是人有判断能力——审批界面必须强制展示责任链快照（谁授权/哪版 SOP/命中哪条策略），否则审批人只是背锅侠；且"人批准 = 责任转移"在法律上未经验证（回到盲区 5）；③全量人审的延迟会吃掉"24 小时数字员工"的 ROI。
- **修正立场**：产品化为策略引擎默认出厂规则——**资金流出类动作默认 require_approval；金额阈值 + 累计限额 + 场景白名单可配；预算内自动执行、超限挂起进收件箱（异步授权）；审批界面强制责任链快照**。原则保留，审批洪水避开。

| 6 | 国产已备案模型 agentic 能力小评测（为双轨与本地化预研） | 假设 1 | 数千元 | P2 |

### 8.4 决策记录（2026-07 创始人 grill 会议）

基于创始人处境四问（目标/客户关系/行业/资源）与逐项压力测试，落定以下决策：

**D1 · 近期目标 = 首批付费客户（不等融资）**，附三条纪律：热客户必须按真实价格付费（可打折不可免费）；验证指标是客户团队的周真实使用量与验收通过数（用自己的 ROI 报表验证自己）；6 个月内至少 1 家非熟人客户，否则 PMF 不成立。

**D2 · Beachhead = HR 招聘，第一个数字员工 = 「寻访/初筛专员」**（依据：热客户在此行业且痛点明确）。该场景与差异化五支柱逐项吻合：验收动作天然存在（HR 逐条过推荐名单）、可解释推荐即证据链、触达候选人是完美的低风险审批熔断训练场、试岗/认证叙事与场景严丝合缝、ROI 对标猎头费（年薪 20–25%）全行业最好算。轻 token 场景（筛 100 份简历约数百万 token），单位经济压力比通用 agent 低一个量级。与北森/Moka 的差异：不做 ATS、不替换系统，做入驻客户现有流程的数字员工，按岗位收费。附带 dogfooding：用自己的数字员工招聘自己的团队。

**D3 · 砍掉的方向**：内容创作（红海+低客单+用不上信任层差异化）；股票量化**不进产品战略**（投顾牌照红线 + 与"钱必须人审"原则自相矛盾）——量化热客户仅可作项目制服务，前提是收入覆盖 6 个月以上 burn 且范围严格限定投研信息处理（不碰交易信号），不进 roadmap 与对外叙事。

**D4 · 团队配置（替代 5–10 人方案）**：创始人（50% 销售/客户现场 + 50% 产品决策，不写代码）+ 资深全栈 2–3 人（重度 AI 辅助，最贵模型的钱花在这里）+ 实习生 1–2 人（只做评测数据集与客户成功，不碰核心代码——评测资产是核心 IP 但多为体力活）+ 设计外包 0.5。月 burn ≈ 15–25 万。原"3–6 名实习生"方案否决：AI 时代初级人力 review/管理成本高于产出。

**D5 · Phase 1 范围改写（通用闭环 → 单岗位闭环）**：6–8 周内，一个寻访/初筛数字员工在 1–2 家热客户处真实上岗：JD 下发 → 人才渠道寻访（MCP 接数据源）→ 初筛评分（附评分理由+来源=证据）→ HR 验收工作台（通过/打回）→ 触达审批 → 约面 → 每周 ROI 报告（寻访人时节省、初筛通过率、到面率）。七闭环通用平台退为 PMF 之后的路线图。

**D6 · 风险优先级更新**：头号平台依赖从"IM 开放性"变更为**简历数据渠道合规**——BOSS/猎聘/脉脉对第三方自动化封禁严格（有判例），合法路径仅三条：企业自有人才库激活（最稳）/渠道官方 API 或企业授权（要谈）/公开信息合规采集（边界模糊）。法律咨询清单增加个保法（PIPL）候选人数据处理义务（告知同意/存储/委托处理协议）。8.3 行动清单相应重排：#3 改为"简历数据渠道合规尽调（P0）"，IM 尽调降为 P2。
（修订：因 D7 确认公司自有 HR 团队与自有简历库，渠道尽调从"开工前置条件"降级为"**外部渠道扩展的前置条件**"——内部上岗用自有简历库先行，尽调并行。）

**D7 · 人员配置定稿（2026-07 补充；月 burn 12–20 万，预算上限 10–25 万/月内）**

前提事实：技术骨干中有人做过 LLM 生产项目（无需外聘 agent 工程）；公司自有 HR 团队（领域知识内部借调）；公司市场部承接需求验证与 GTM 物料。

| 角色 | 谁 | 投入 |
|---|---|---|
| 技术负责人（兼 agent 工程） | 有 LLM 生产经验的骨干 | 全职 |
| 全栈 ×2 | 现有骨干 + 重度 AI 辅助开发 | 全职 |
| 产品 + 交付 | 创始人（不写代码） | 50% 客户现场 / 50% 产品决策 |
| HR 领域知识 | 公司 HR 负责人借调（10–20%）共建 rubric + 热客户 HR design partner | 借，不招 |
| 评测 / 支持 | 实习生 ×1–2（评测集、简历脱敏，不碰核心代码） | 全职 |
| 点状外部 | 法务一次性（PIPL + 合同模板 1–2 万）、架构顾问可选 | 按需 |

暂不招聘（写明触发条件）：客户成功（M4 前创始人扛，签第 4 家客户时招）、资深平台后端（签第 3 家**陌生**客户前招）、猎头顾问（公司 HR 替代）。配置原则：按阶段配人而非按终局配人；"整个项目做不到"是伪命题——当前团队只需做到 Phase 1 单岗位闭环。

**D8 · 落地路线定稿（M0–M6）**

- **M0（2 周，三线并行）**：① 技术 spike——筛 20 份真实简历、每份带理由评分、全程事件可回放（验证团队能力与架构选型）；② 简历渠道合规尽调（并行，不阻塞）；③ 定价工作坊——创始人+市场部+1 家热客户，敲定「岗位订阅 ¥2,000–4,000/月 + 按确认到面 ¥100–300/人加价」报价单（招聘是按结果计费最可行场景：到面/offer 事件清晰可验证，锚点为猎头费 20–25% 年薪）。
- **M1–M2 内部上岗（第 0 号客户 = 公司自己的 HR 团队）**：用自有简历库跑真实招聘（含招聘本项目缺员），rubric 迭代至 HR 负责人认可；同时产出 dogfooding 销售素材。合规风险最低（自有投递简历）。
- **M2–M3 热客户付费上岗**：1–2 家，真实价格（可打折不可免费），7 天试岗→转正动线即销售动线。
- **M3–M4 PMF 判据**：第一份对外 ROI 报告（寻访人时节省/初筛通过率/到面率）+ 拿下第 1 家非熟人客户。
- **M4–M6 产品化起步**：多租户/审计账本等编制管理基础（对应第 6 章 Phase 2 前半），招客户成功 1 名；资深后端按 D7 触发条件招聘。
