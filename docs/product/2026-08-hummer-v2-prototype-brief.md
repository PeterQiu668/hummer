# HUMMER V2 企业级 Agent 操作界面原型说明

状态：`可交互前端原型，未接入真实 Desktop Worker`  
版本：0.2  
日期：2026-08-25  
关联：`2026-08-market-entry-analysis.md`、`2026-08-technical-product-spec.md`、`2026-08-hummer-v1-prototype-spec.md`

## 1. 调整原因

V1 将“可信 WorkOrder 闭环”表现得过于像一个轻量任务看板，弱化了 HUMMER 最有辨识度的企业操作界面：公司总部、人机组织、员工市场、能力/MCP、协作、治理和进化。

V2 不替换现有的企业总部原型，而是把它收敛为一条完整叙事：

```text
老板驾驶舱 / 公司总部
-> 分身与部门接收目标
-> 数字员工在本地执行工作台组队
-> 受控文件、浏览器与桌面会话推进任务
-> 人工审批高风险动作
-> ResultPackage、证据、审计、ROI 与 bad case 进化
```

## 2. V2 的六层操作界面

| 层 | 现有/新增入口 | 用户看到的企业能力 |
| --- | --- | --- |
| 组织指挥层 | `指挥中心`、3D 公司总部、右侧分身链路、底部协作流 | 老板目标、部门状态、人机责任链、异常与审批 |
| 角色工作层 | 高管工作台、我的 AI 同事 | 高管确认分身拆解、验收交付；员工派活、催办、验收 |
| 本地执行层 | `本地执行工作台`，V2 新增 | WorkOrder 作用域内的文件、浏览器、桌面会话、并行子任务、检查点与暂停 |
| 编制与能力层 | 我的员工、员工市场、技能与工具、MCP 连接、知识中枢 | 招人、试岗、上岗、技能/MCP/知识装配、能力缺口 |
| 可信交付层 | 工作任务、交付物、收件箱、审计与治理、ROI | 军令状、审批、成果、证据、出口动作、成本和责任 |
| 进化层 | 进化中心、专家门户 | bad case、评测、SOP/技能改进、专家介入和灰度发布 |

## 3. 本地执行工作台的产品定位

它不是“把用户电脑交给 AI”，而是把 Codex/WorkBuddy 一类产品的有效体验翻译成企业控制面：

| 借鉴点 | HUMMER 中的产品化表达 | 企业约束 |
| --- | --- | --- |
| 本地工作区 | WorkOrder 绑定的文件、浏览器、应用和桌面会话 | 任务作用域、时限与 tenant 隔离 |
| 多 Agent 并行 | Manager-Workers 子任务队列 | 每个子任务有 owner、输入、输出和检查点 |
| 任务持续推进 | 可暂停、恢复、升级和交接 | 令牌收回、异常可见、人工可接管 |
| 本地工具调用 | 受控文件/浏览器/桌面工具清单 | 白名单、短期令牌、高风险动作独立审批 |
| 过程与最终交付 | 执行轨迹、证据摘要、ResultPackage | append-only 审计、脱敏和回滚信息 |
| 工作规范 | 版本锁定的 Skill/SOP/知识包 | 发布、评测和权限均可治理 |

V2 中所有资源均为合成数据。界面明确标记为原型，不能据此声称已连接 Codex Desktop、WorkBuddy、用户文件、浏览器账号、CRM 或真实 MCP。

## 4. V2 关键交互

1. 老板或员工从左侧导航或命令面板进入 `本地执行台`。
2. 系统显示当前 WorkOrder、数字员工执行小组、资源清单、权限边界和会话有效期。
3. 人工申请一次受控桌面会话；会话进入“待审批”。
4. 人工批准后才可启动并行执行；每个子任务在独立工作区产生轨迹和检查点。
5. 人工可随时暂停；暂停即收回桌面令牌，工作保留在检查点。
6. 执行产物通过证据库进入成果验收；真实写入或外发仍需单独审批。

## 5. 设计原则

- **保留操作密度。** 原始公司总部、员工市场、MCP、治理、审计和进化继续是主流程，不退化成单页面仪表盘。
- **让“桌面能力”可见。** 用户看到资源、作用域、工具、会话、子任务和证据，而不是模糊地看到“AI 正在干活”。
- **角色不同，事实一致。** 老板、高管、员工、专家、审计员只是不同投影，均回到同一任务、员工、能力和审计对象。
- **将开源 runtime 放在底座。** Codex、DeepSeek Harness、OpenClaw、AgentTeams、LangGraph 等将通过 RuntimeAdapter/Tool Gateway 接入；不会成为组织事实源。
- **高权限默认不可得。** V2 先展示 L2 审批执行。真实文件/桌面/写入授权、密钥、录屏证据和 kill switch 由 Phase 1 后端实现。

## 6. 当前实现与后续边界

本轮已经实现 V2 前端原型：`DesktopWorkstationPage`、角色导航、全局命令面板入口和会话状态交互；相关交互写入当前原型的 mock audit/toast，不等价于服务端事实。

进入可信 MVP 开发时，V2 页面必须由 `WorkOrder`、`Approval`、`RuntimeJob`、`Evidence`、`ResultPackage` 和 append-only `DomainEvent` 投影驱动。真实 Desktop Worker 只可经 `RuntimeAdapter` 与受控 Tool Gateway 访问本地资源。

## 7. 原型验收

- 旧版丰富的公司总部、组织、员工、市场、MCP、治理、审计、ROI、进化入口仍可访问。
- 新本地执行台清晰展示一个任务的数字员工小组、资源、权限、轨迹、证据和交付链路。
- 未审批的会话无法启动；会话运行后可暂停并显示令牌收回。
- 页面与全局搜索、任务、MCP 连接和证据库互相可跳转。
- 所有本地资源都明确是合成演示，不把前端 mock 描述为真实接入。
