## 1. 新增对标：HiClaw 与 WorkBuddy 改变了什么

### 1.1 阿里 HiClaw（开源，Higress 团队；商业版 AgentTeams）

关键事实：Manager-Worker 多智能体架构；人类全程可见、随时可介入的**受控可审计 IM 房间**（内置 Matrix 服务器）；Worker 只持**「工牌」式令牌，永不接触真实密钥**；支持私有化部署；Apache 2.0；配套 CoPaw 直接操作本地环境；叙事是"一人一公司/企业数字员工化"。

对 Hummer 的三层含义：

1. **编排层彻底商品化（威胁确认）**。开源 + 云厂商托管的多 Agent 协同运行时已经免费可得。调研结论"搭建平台是红海"现在延伸到"协同运行时也是红海"——Hummer 绝不能把 Orchestrator 当护城河来投入，五支柱（责任链 / 认证 / 专家生态 / FinOps / 闭环工作系统）作为 HRM 层的定位**更加正确而且更加紧迫**。
2. **HiClaw 可以是零件而不是对手（机会）**。架构文档 §5.1 平台层的 `Orchestrator + Agent Runtime` 可将 HiClaw 列为候选运行时（国产、开源、可私有化、备案通路比 Claude 内核友好，与 §7.2 双轨策略吻合）。Hummer 在其上做编制 / 认证 / 追责 / 结算——「HiClaw 管跑，Hummer 管人事」。
3. **「工牌令牌」值得直接吸收（产品语言）**。凭证隔离（agent 永不碰真实密钥）本来就在 infra-standards 的 Token Vault 方案里，但 HiClaw 把它讲成了"工牌"——这是比"Token Vault"好十倍的产品叙事。落点见 §2.3 授权仪式改造。

### 1.2 腾讯 WorkBuddy（桌面本地执行智能体 + 企业版管理平台）

关键事实：桌面端本地执行（自主拆解任务、操作本机软件、交付可验收成果）；多 Agent 并行；后台自动化 + 定时任务（7×24 叙事）；接入微信 / 飞书 / 钉钉 / 企微 / QQ；企业版 = CodeBuddy + WorkBuddy + **企业管理平台（运行观测 / 效果评估 / AI 资产管理）**。

对 Hummer 的三层含义：

1. **巨头开始卖"数字员工管理平台"了（窗口收窄确认）**。WorkBuddy 企业版的管理平台（观测/评估/资产）正是 Hummer 平台层的一部分。防御依据不变且强化：跨平台中立性 + 认证/审计资产可迁移 + 责任链/结算这些腾讯没做的深水区。D2（HR 招聘 beachhead）的执行紧迫性提高——通用层拼不过巨头捆绑，垂直闭环先落地。
2. **桌面执行端从"远期选项"升级为"行业标配"（意见七的外部佐证）**。WorkBuddy 本地执行 + 阿里 CoPaw 操作本地环境 + 实在智能 TARS-VL 屏幕语义——三家共同宣告：数字员工必须能操作没有 API 的存量软件。详见 §2.4。
3. **IM 触角策略被验证**。WorkBuddy 接五大 IM 与假设 2 修正立场（"驾驶舱自持、IM 只做触角"）一致，不改。

## 2. 四点意见展开

### 2.1 意见一：责任链 v2 — 从固定五级叙事到动态担责路由

**老板原话**：老板 → 老板分身 → 高管分身 → 真人高管 → 一线员工 → 数字员工；若高管下面没有一线员工，则高管分身直达数字员工；高管也可以直接指挥数字员工，**高管指挥就是高管担责**。

**现状问题**：原型的责任链是硬编码五级叙事（RightConsole 常驻、ChainSnapshot 快照），**一线员工不在链上**（Phase 0 加了 StaffWorkspacePage 但责任链模型没接），且链是"固定图"而不是"每个任务实际走过的路"。

**核心原则（一句话产品化）**：**指挥即担责（Command = Accountability）**。责任人不由组织架构静态决定，而由"谁把任务派给了数字员工"动态决定。

设计：

1. **完整链形态**：`老板 → 老板分身 → 高管分身 → 真人高管 → 一线员工 → 数字员工`，允许两类合法短路：
   - 高管无下属一线员工 → `高管分身 → 数字员工`（担责人 = 该高管）；
   - 真人（高管或一线）直接指挥数字员工 → 担责人 = 该真人。
2. **担责判定规则（Accountability Resolver）**：每个任务记录 `commandPath`（实际指挥路径，节点 = 人/分身/数字员工）；担责人 = 路径上**距离数字员工最近的真人**。分身不能担责——分身的动作责任穿透到其 owner 本人。
3. **担责确认微交互**：真人直接给数字员工派活时，任务创建界面显式提示「此任务由你担责」并入 grant/审计——这是把"指挥即担责"从制度变成 UI 合同的一步，也预防审计时的"我不知道我要负责"。
4. **责任链快照升级**：ChainSnapshot 从展示固定五级改为渲染该任务的真实 `commandPath`，担责人高亮，短路路径显式标注（"高管直接指挥"徽章）。

文件级改造（Phase 0.5，纯 mock 可做）：

| 文件 | 改动 |
|---|---|
| `lib/types.ts` | `CollabTask` 增加 `commandPath: ChainNode[]` 与 `accountableId: string`；新增 `ChainNode { actorId; actorName; kind: 'human'|'avatar'|'agent' }` |
| `store/useAppStore.ts` | `addTask` 时按当前角色 + 目标员工推导 commandPath 与担责人 |
| `components/audit/ChainSnapshot.tsx` | 渲染真实路径 + 担责人高亮 + 短路徽章 |
| `components/shell/RightConsole.tsx` | 固定五级图 → 动态"本任务责任路由"示例 |
| `pages/StaffWorkspacePage.tsx` / `ExecWorkspacePage.tsx` | 派活动线加「此任务由你担责」确认条；派活后任务卡显示担责人 |
| `docs/hummer-product-architecture.md` §4 支柱一、§5.2/5.3 | 五级链改为"六级全链 + 两类短路 + 指挥即担责"表述 |

### 2.2 意见二（6）：任务复杂度自动评估 → 自动分配 Agent 与担责人

**老板原话**：判断任务复杂度，自动分配 agent 和相应的负责人。

**现状问题**：任务从对话 decompose / 会议行动项 / 收件箱产生后，指派靠手选；复杂度概念不存在。

设计——**任务受理器（Task Triage）**，一个机制同时解决三件事：

1. **复杂度评级**：任务创建时按五因子打分——涉及工具数 / 数据敏感度 / 是否涉钱 / 交付时限 / 跨部门协作——产出 `simple | standard | complex | critical` 四级。
2. **自动分配 Agent（与支柱二认证联动）**：只有**认证等级 ≥ 任务复杂度**的数字员工才可被自动指派（持证上岗从叙事变成调度约束）；complex 以上自动组 supervisor+workers（对齐 MultiDevin / HiClaw Manager-Worker 共识）。
3. **自动判定担责人（与 §2.1 联动）**：按发起人的 commandPath 规则推导；**critical 级任务担责人自动上移一级**（一线发起的 critical 任务担责人升到其高管），并进收件箱要求确认。
4. **与模型分层路由是同一件事（P0 生存问题连线）**：架构文档 §7.4 已把"模型分层路由"定为毛利生死线——复杂度评级正是路由信号（simple → 轻量模型，critical → 旗舰模型）。一次建设，同时服务调度、担责、成本三件事。**这条连线建议直接写进架构文档 §7.4。**

用户可覆盖自动分配（换人/改级），覆盖动作本身留痕入审计。

| `store/useAppStore.ts` | `addTask` 内嵌 triage 函数（mock 规则打分）；critical 上移担责人 + 推收件箱 |
| `components/collab/TaskCard.tsx` / `work/TaskDrawer.tsx` | 复杂度徽章 + 「自动指派」标注 + 担责人 + 覆盖入口 |

### 2.3 意见八：专家咨询商业化 — 计费、评价、工单关闭权

**老板原话**：咨询专家收费按次/按月订阅；回答完用户评价，计入专家业绩；**工单由用户决定关闭，而不是专家**。

**现状问题**：`ExpertTicket.status` 是 `open → responding → resolved`——**resolved 由专家侧宣布，用户无确认权**；专家收入（RevenuePanel）只有 Agent hires 分成，没有咨询收费；评价维度不存在。

设计：

1. **工单状态机改造（关闭权归用户）**：
   `open → responding → expert_submitted（专家提交解决方案，等用户确认） → closed（用户确认关闭 + 强制评价） / reopened（用户打回，SLA 重新计时）`。
   专家侧 TicketBoard 的按钮从「标记解决」改为「提交解决方案」；用户侧（老板/高管/一线均可发起咨询）获得确认/打回/评价入口。超 N 天未确认自动关闭前推收件箱提醒（防止用户侧拖挂损害专家 SLA 统计——公平性双向）。
2. **两种计费 SKU**：按次咨询（单价随专家等级浮动）+ 包月订阅（相当于"外聘顾问编制"，含 SLA 等级）。与套餐挂钩：旗舰套餐内含 N 次/月。
3. **评价即业绩**：关闭工单时强制三维评分（响应速度/专业度/解决度）→ 计入专家声誉（ReputationPanel 已有雏形）→ 声誉决定曝光、定价权、分成比例——**把成长闭环数据变成生态货币的既有设计，现在多了一条真实数据来源**。
4. **与支柱四连线**：咨询消费进账单中心（部门归因），咨询节省的介入人时进 ROI 月报。

|---|---|
| `lib/types.ts` | `ExpertTicket.status` 扩为五态；增加 `rating?: { speed; expertise; resolution }`、`billing: 'per_case'|'subscription'` |
| `data/expertops.ts` | mock 工单补五态样例 + 咨询计费记录 |
| `components/expert/TicketBoard.tsx` | 「标记解决」→「提交解决方案」；显示等待用户确认态 |
| `components/expert/RevenuePanel.tsx` | 增加咨询收入行（按次 × 单价 + 订阅） |
| `components/expert/ReputationPanel.tsx` | 接入评价三维度均分 |
| 用户侧新增 | 「咨询专家」入口（boss/exec/staff 可见，建议挂在 TopBar 或收件箱）+ 我的咨询列表（确认关闭/打回/评价） |
| `pages/RoiPage.tsx` | 账单加咨询消费项 |

### 2.4 意见七：桌面执行端 — 数字员工的"手"

**老板原话**：数字员工真正要执行还需要相应的桌面端执行自动化程序。

**外部佐证**（本次对标新增）：腾讯 WorkBuddy 桌面本地执行、阿里 CoPaw 操作本地环境、实在智能 TARS-VL 屏幕语义免 API 操作——2026 年共识：**没有桌面执行能力的"数字员工"只能处理有 API 的世界，而中国企业的存量软件大多没有 API**。

设计——**执行舱（Hummer Desktop Runner）**：

1. **定位**：装在企业内指定工作机上的执行客户端，数字员工经它操作本地软件（ERP 客户端 / 网页后台 / Excel / 邮箱）。架构上是 L2 平台层 `Agent Runtime` 的第二种执行体：`云端执行（MCP 工具） + 桌面执行（computer-use）`。
2. **治理是差异化，不是执行本身**（执行能力巨头都有，受控执行没人做全）：
   - 桌面动作同样过策略引擎与审批熔断（高危操作先挂起）；
   - **全程屏幕录制 + 操作轨迹入证据链**——这是 Hummer 独有的增强：桌面执行的每一步都是带 hash 的证据，别家的桌面 agent 是黑箱，Hummer 的桌面 agent 是"带工牌、有录像、可回放"的；
   - 凭证隔离采用 HiClaw 工牌模式：Runner 持短期任务令牌，真实账号密码在 Token Vault，agent 永不可见。
3. **边界纪律（衔接 D6）**：执行舱用于**企业自有系统**；对封禁自动化的第三方平台（BOSS/猎聘等）不做绕过——桌面端不是合规问题的后门。
4. **分期**：
   - **Phase 0.5（原型可做）**：3D 指挥中心 / 员工详情增加「执行舱」视图 mock——正在执行的桌面任务卡（软件名 + 当前步骤 + 实时轨迹时间线 + 「查看录屏」占位 + 熔断按钮）。演示叙事一句话："数字员工不只在云端调 API，还在这台电脑上真的干活，每一步有录像可回放。"
   - **Phase 1（HR beachhead 内）**：真实 Runner 最小版可选——寻访员工操作企业自有人才库网页端（Playwright/computer-use 二选一），轨迹入证据。
   - **Phase 2**：正式客户端（授权仪式绑定设备、多机调度、录屏证据管道）。

## 4. 对五支柱的影响小结

| 支柱 | 变化 |
|---|---|
| 一 责任链 | **升级**：五级固定链 → 六级全链 + 短路规则 + 指挥即担责 + 桌面写操作治理 |
| 二 认证绩效 | **增强**：认证等级成为任务受理器的调度约束（持证上岗 → 持证接单） |
| 三 专家生态 | **纠偏**：工单关闭权归用户 + 咨询双 SKU + 评价即业绩，声誉体系拿到真实数据源 |
| 四 ROI/FinOps | **连线**：复杂度评级 = 模型分层路由信号（毛利生死线的实现载体）；咨询消费入账单 |
| 五 闭环工作系统 | **扩展**：执行舱作为第五个工作面（云端之外的"手"），录屏轨迹入证据链 |

定位一句话不变且被两家大厂新品反向验证：**编排与执行正在商品化（HiClaw/WorkBuddy 免费送），雇佣、授权、考核、追责、结算没人做全——Hummer 做数字员工的人事与信任基础设施。**
