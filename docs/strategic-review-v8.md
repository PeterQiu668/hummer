# Hummer 战略重审 v8 — 根本性创新、产品形态与 AGI 变量

> 2026-07-04 · 视角设定：顶尖产品总监（Google 的"原语与标准"思维 × 腾讯的"场景与分发"思维）对现有产品的无情重审。
> 前置文档：`hummer-product-architecture.md`（五支柱 + D1–D8）、`phase0.5-revision-proposal.md`（四点意见机制化）。本文不推翻它们，但指出它们共同的盲区：**机制都对，形态错了；功能都全，原语没有。**

## 1. 解剖两个划时代产品：OpenClaw 与 Hermes 到底赢在哪

| | OpenClaw（2026.01，100k stars） | Hermes Agent（2026.02，Nous Research，两月 4.7 万星） |
|---|---|---|
| 划时代一击 | 把 LLM 接上**真实软件**（本地执行、发邮件、控制 API），"会做事而不是会聊天" | **持久记忆 + 自我进化**（跨会话 FTS5 记忆、自主创建技能），"越用越强的 agent" |
| 存在形态 | 住在你的 IM 里（联系人，不是网站） | 住在你的服务器上，通过 Telegram/Discord/WeChat 触达 |
| 分发 | 开源 + BYO API key + 开发者病毒传播（72 小时 6 万星） | 同左；后来单日 2710 亿 token 登顶 OpenRouter，反超 OpenClaw |
| 商业模式 | 没有（这是关键情报，见下） | 没有 |

**五条共同基因**：① 一个可一句话说清的新原语；② 存在（presence）而非目的地（destination）——用户不"访问"它，它"在"用户身边；③ 做事不聊天；④ 骑在模型浪潮上（BYO key，模型每升级产品自动变强）；⑤ 自下而上传播，第一天就能被一个人用起来。

**它们没有的东西**（= 它们留下的划时代空位）：多人/组织、问责、预算、验收、合规、结算。OpenClaw 和 Hermes 解决了"**一个人**如何拥有一个能干活的 agent"；没有人解决"**一群人**如何信任一群 agent 干活"。**上一个时代的划时代产品降低了"智能的摩擦"；下一个划时代产品要降低的是"信任的摩擦"。这就是 Hummer 的位置——但现在的产品形态承载不了这个位置。**

## 2. 对现有产品的五个尖锐问题

### Q1 你的产品是"目的地"还是"存在"？

现状：13 个左导航项、五角色切换、3D 指挥中心——这是一个**要求用户每天专程访问的 ERP 式控制台**。而 2026 年已被反复验证的事实是：agent 赢在存在感（IM 联系人、桌面常驻、群成员），控制台输在"想不起来打开"。企业软件史的铁律：**被访问的系统会死于低频，嵌入工作流的系统才有日活。**

诊断：Hummer 把 90% 的设计预算花在了"观看层"（3D 办公室、页面、看板），10% 花在"发生层"（任务真正流转的对话流）。比例应该倒过来。

### Q2 你在模拟人类组织，还是在发明 agent 原生组织？

现状：老板分身、高管分身、分身开会、体素小人在工位走动、试岗 7 天、末位淘汰——整套是**对人类公司的拟物化模拟（skeuomorphism）**。拟物化的历史规律：早期汽车做成马车形状帮助用户理解，但划时代的是福特 T 型车扔掉马车壳。

要害区分——模拟里哪些是**真需求**、哪些是**剧场**：

| 真需求（留下并深挖） | 剧场（降级为演示皮肤） |
|---|---|
| 责任归属（出错找谁）| 分身"开会"的仪式动画 |
| 权限分级与渐进信任 | 体素小人走动、休息区 |
| 验收与质量关卡 | "试岗第 7 天"这类拟人日历（真正的信任单位是**连续通过的验收次数**，不是天数）|
| 预算与结算 | 组织架构树状图（agent 组织是动态图，不是树）|

剧场有融资演示价值，可以保留为"演示模式"；但产品本体必须建立在真需求的抽象上。**用户买的不是"像公司"，是"可问责"。**

### Q3 你的新原语（primitive）是什么？

OpenClaw 的原语："agent 作为 IM 联系人"。Hermes 的原语："自我进化的持久 agent"。Git 的原语：commit。**Hummer 现在没有原语——它有 13 个功能页面，但没有一个可以被一句话定义、被行业借用的最小新概念。**

候选原语已经埋在代码里没被点破：**工作提交（Work Commit）**。

> 每一次 agent 动作 = 一条不可篡改的记录：**谁（agent 身份）+ 受谁指挥（commandPath）+ 谁担责（accountable human）+ 依据什么（SOP 版本/授权额度）+ 产出什么（证据 hash）+ 花了多少（token/费用）+ 谁验收（judgement）**。

这就是"git commit 之于代码变更"的"work commit 之于 AI 工作"。现有的审计账本、证据链、责任链快照、验收判定——全都是这个原语的碎片，散落在五个页面里。**把它收拢、命名、协议化，Hummer 就从"一个管理软件"变成"一个记账标准"。** 划时代产品的终极形态不是 app，是标准（TCP/IP、Git、MCP）。

### Q4 你的增长引擎是什么？

OpenClaw/Hermes 靠开源病毒。Hummer 是企业产品，等价物是什么？现有规划（D1：创始人跑客户）是销售，不是引擎。腾讯 PM 视角的答案——**中国 B2B 的病毒回路在"群"里**：

1. **数字员工入群是原子采用事件**。不是"企业采购了平台"，而是"这个群里多了一个能被 @ 的数字同事"。群里的每个真人（包括客户的客户、合作方）都是目击者。
2. **可转发的工作凭证**。ROI 月报做成可分享海报；数字员工有"工牌名片"（认证分、完成任务数、担责人）可以被转发到别的群——老板圈层的攀比即传播。
3. **验收通过的交付物自带署名**："本报告由 Hummer 数字员工完成 · 验收人 XXX · 证据可回放"——每一份交付物是一张传单。

北极星指标建议（Google PM 视角）：**每周被验收通过的交付物数（Weekly Accepted Deliverables）**。不是对话数、不是 token 数、不是登录数——只有"被人类验收通过的真实工作"才是价值本体。激活定义：客户接入后 24 小时内完成第一次真实验收。

### Q5 AGI 来了，你的产品还剩什么？

推演三档：

- **今天（agent 可靠性 60-80%）**：人工验收、审批熔断、专家兜底都是刚需 → 现有设计成立。
- **两年后（可靠性 95%+，长任务自主）**：逐条审批变成瓶颈和羞辱，"管理界面"日活归零 → 只留下**例外管理**（预算越界、策略触发、抽检）。
- **AGI 级**：数字员工不需要被"管理"，但**责任、预算、保险、合规审计反而更需要**——因为动作量指数级增长而人类问责容量恒定。监管（EU AI Act、国内双备案）保证了这一层永远有人买单。

结论：**Hummer 赌的"信任层"恰好是 AGI-proof 的——但有一个前提：所有人工触点必须被设计成"可拆除的脚手架"，而不是产品本体。** 具体检验标准：任何一个"需要人点一下"的环节，都必须回答"当 agent 可靠性达到 X% 时，这一步如何自动消失，消失之后这个界面还剩什么"。答不出来的环节就是未来的死代码。

由此得出 AGI 时代的核心交互物：**自治度旋钮（Autonomy Dial）**，L0 每步审批 → L4 只看结果。信任生产函数：连续 N 次验收通过 → 系统主动建议升档（升档 = 一次新的授权仪式，留痕）。**Hummer 的本质从"管理 agent 的软件"变成"生产信任的机器"——它的产出不是任务完成，是"这个 agent 可以被信到什么程度"的可验证记录。** 这个记录跨平台可迁移（换模型、换运行时，信任档案跟着走）——这才是没有人做、巨头难做（利益冲突：他们要锁定）、且越到 AGI 越值钱的东西。

## 3. 产品形态重构：从 13 个页面到「一流一台一账」

### 3.1 新信息架构

```
┌─ 流 The Stream ──────────────────────────────────────────┐
│ 产品本体。对话 + 事件 + 结构化卡片（任务/审批/验收/证据/工单）  │
│ 同构分发到：Web 主界面 = IM（企微/钉钉/飞书）bot = 移动端     │
│ 9 种消息类型是现成资产——它们本来就该是主界面而不是功能之一     │
├─ 台 The Desk ────────────────────────────────────────────┤
│ 每角色一个屏，全部收件箱驱动（队列，不是仪表盘）：             │
│ 老板=决策队列 · 高管=验收队列 · 一线=我的AI同事 · 专家=工单    │
│ 原 13 页里的市场/技能/MCP/知识 → 降为"台"内的抽屉与设置       │
├─ 账 The Ledger ──────────────────────────────────────────┤
│ 工作提交账本 = 审计+证据+账单+ROI 四页合一                    │
│ 对内是管理报表，对外是可导出的「AI 工作凭证」（审计/保险/监管）  │
└──────────────────────────────────────────────────────────┘
3D 办公室 → 降级为「演示模式 / 大屏模式」（融资、前台大屏、老板炫耀用），
永不承担导航职能。
```

### 3.2 交互体验的三个再设计

1. **把审批时刻当成产品的灵魂时刻来设计**（Superhuman 之于邮件）。现状审批散在弹窗和页面里；应统一为一种卡片：上半张是"发生了什么"（一句话 + 证据缩略），下半张是"你在为什么担责"（责任链快照内嵌 + 额度消耗 + 复杂度级），底部两个大按钮。全键盘操作，移动端一屏一卡上滑即批。**老板的全部使用可以收敛为：躺在沙发上刷决策队列，像刷短视频。** 这是"体验感"的真正答案——不是 3D 炫，是决策爽。
2. **每个对象可对话**（agent 原生交互原则）。任务卡、证据、账单行、数字员工——一切实体长按即可追问（"为什么超预算""这个结论的依据"），由对应 agent 用证据链回答。查询界面消失，UI 退化为对话的书签。
3. **进度的诚实呈现**。mock 实时引擎现在每 5 秒推假事件制造繁忙感——上线后这会立刻反噬信任。原则改为：**只推需要人动作的事件 + 已验收的成果**；过程性噪音全部收进可展开的执行轨迹（执行舱时间线）。安静的产品才像可靠的员工。

### 3.3 与既有决策的关系

- D2（HR beachhead）不变——划时代愿景需要载体，寻访/初筛数字员工就是"work commit 原语"的第一个宿主：每条候选人推荐 = 一次带评分理由与来源的工作提交，天然完美示范。
- Phase 0.5 四点意见（责任链 v2 / 任务受理器 / 执行舱 / 专家工单）不变，但**实现顺序服从形态重构**：先把"流"立为主界面，四个机制作为卡片类型长在流里，而不是四个新页面。
- 架构文档 §5.1 体验层重写为"一流一台一账 + 演示模式"。

## 4. 划时代的路线：开放协议赌注（可选但值得严肃评估）

Google 式打法：**把互补品商品化，把标准据为己有。**

- 编排与执行已被 HiClaw/WorkBuddy/OpenClaw/Hermes 商品化 → 顺势而为，全部兼容接入（Hummer 不生产 agent，Hummer 给任何 agent 发工牌、记账本）。
- 把「工作提交 / 责任链快照 / 信任档案」做成**开放规范 + 开源参考实现**（像 MCP 之于工具接入）：任何 runtime（HiClaw 的房间、OpenClaw 的会话、企业自研）都可以往 Hummer 账本写 work commit。
- 商业化留在管理平面：多租户账本托管、认证服务、保险对接、合规导出、专家生态抽成。
- 中国语境的顺风：双备案 + 等保 + 即将到来的 AI 责任险，都需要"AI 干了什么、谁负责"的标准凭证。**谁定义凭证格式，谁拿走监管红利。** 这是创业公司唯一能在巨头夹缝里"定标准"的窗口——巨头做不了中立记账方（既当运动员又当裁判）。

风险照实说：协议冷启动比产品冷启动更难，需要 PMF 之后再启动（Phase 2/3），但**架构上第一天就要按"账本可被第三方写入"设计**（事件 schema 即协议草案），否则日后拆不出来。

## 5. AGI 要不要考虑进去 — 直接回答

**作为设计约束：要，且已给出三条硬规则**——① 每个人工触点可拆除（脚手架检验）；② 自治度旋钮 + 信任生产函数是核心对象而非设置项；③ 组织结构做成 descriptive（记录 agent 实际委派图）而非 prescriptive（预画组织树），A2A 自组织时代组织图是涌现出来的。

**作为营销叙事：不要。** 企业客户 2026 年买的是"出错找谁 + 花多少钱 + 到底有没有用"，AGI 叙事只会触发采购的恐惧和合规的警觉。对外一个字不提 AGI，对内每一个架构决策都按"模型能力两年翻两番"来压力测试。

**一句话收束**：OpenClaw 让个人拥有了 agent，Hermes 让 agent 拥有了记忆；Hummer 要做的是让**组织**拥有信任 agent 的能力——当智能免费的时候，信任就是最后的稀缺品，而信任需要账本。
